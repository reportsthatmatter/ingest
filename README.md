# @rtm/ingest

PDF → Markdown for public inquiry reports, deterministically.

PDF → Markdown, deterministically. The same inputs always produce the same
output, so a report can be regenerated by anyone, at any time, from its own
definition.

Used by [reportsthatmatter.org](https://reportsthatmatter.org). Architecture
and the reasoning behind it live in the site repo:
[`docs/plans/2026-08-28-ingestion-architecture.md`](https://github.com/reportsthatmatter/reportsthatmatter/blob/main/docs/plans/2026-08-28-ingestion-architecture.md).

## Install

```json
"@rtm/ingest": "github:reportsthatmatter/ingest#v0.1.0"
```

A git dependency, not a submodule: pnpm fetches it into `node_modules` pinned
to that tag, and each consumer adopts a new version deliberately. That is what
makes "a report adopts pipeline improvements on its own schedule" real rather
than aspirational — nothing arrives unannounced.

## The shape

```
<report>/ingest.ts         the report's own pipeline — what it declares
        │
        ▼
  acquire → extract → segment → structure → render
        │       │        │          │          │
   volumes,  poppler   page      blocks     full.md
   checksums           passes    + geometry  baseline.json
                                             fidelity.md
```

Every page and every block carries `{ volume, pdfIndex, printed }`, so a
review note can say *Vol 2 · PDF p.412* rather than a flat index into a
document that does not exist as one file.

## What a pass is

One named decision about how to read a source. A report composes them:

```ts
export default pipeline({
  id: "uk-leveson-inquiry",
  repo: "../uk-leveson-inquiry",
  volumes: [{ path: "archive/0780_i.pdf", sha256: "…" }, …],
  passes: [geometry("per-volume"), runningFurniture()],
});
```

**A pass never takes a regex or a pattern.** It selects among implemented,
tested behaviours. The moment a report's definition can express a pattern, it
has become a second parser with no tests of its own.

**`resolvePasses` throws on a page pass it does not implement** (`KNOWN_PAGE_PASSES` in `src/define.ts`): a report's `ingest.ts` is imported from the report's own `node_modules`, so a report declaring a pass added in a newer library than the one the host runs would otherwise get output with the pass silently missing (reportsthatmatter-5xln). Adding a page pass means adding its name to that list; `tests/resolve-passes.test.ts` fails until you do.

A report that genuinely needs something bespoke writes its own pass in its own
file. That is the escape hatch, and it is a staging area rather than a
destination: **when a third report needs the same pass, move it in here.** If
two reports independently fork the same pass, that is the signal to fix the
shared one, not to accept the fork.

## The rule about where a fix goes

| | |
| --- | --- |
| Holds for every document in the corpus | a shared pass, here |
| A property of *this source* the parser cannot infer | a pass the report declares |
| A judgement about *this document's text* | `corrections.yaml` (not built — #106) |

If you are writing a correction to undo something the parser did, you needed a
different pass or a bug fix.

## The PDF's layout

`pdftotext -layout` gives the pipeline each line's text and leading spaces. The PDF also knows each line's position, font, size and colour; `pdftohtml -xml` (the same poppler) reports them. `openLayout(pdfPaths, cacheDir)` reads that once per PDF, caches the XML at `<cacheDir>/layout-<sha256 of the PDF>.xml` (the host passes `<report-repo>/.cache`, which gets a `.gitignore` of `*` inside it), and returns a `Layout`:

```ts
layout.lines(volume, pdfIndex)   // LayoutLine[], in reading order; the same volume and pdfIndex as a Page or a block's `at`
layout.page(volume, pdfIndex)    // margin, right edge, line pitch, body font of the page
layout.bodyFont                  // the document's body font
```

Each `LayoutLine` carries `top`, `left`, `width`, `height`, `right`, `family`, `size`, `color`, `bold`, `italic`, a `font` key, `body` (set in the body font), `raised` (small raised digit runs: marker shapes, each with its `offset` in the line's text; a run poppler emits after the text that follows it is put back where it sits), `label` (opens on "57." "(b)" "9.88" a bullet), `indentEm` (left minus the page margin, in ems; negative for a hanging number), `rightGapEm` and `reachesRight` (the line runs to the right margin). `indentVersus(line, next)` is the first-line indent against the line under it, in ems.

A host passes it to the pipeline as `ingestPageGroups(groups, meta, resolved, corrections, { layout })`; volume and body passes receive it as `run(pages, context)` / `run(lines, context, at)`, and `mergeAcrossPages` as `options.layout`. It is lazy: a pipeline that never reads a line never runs `pdftohtml`. Only a pass that opts in reads it, so passing it changes no other output; today that is `layoutPageJoins` and `layoutMarkers` (below). `IngestResult.blocks` carries the final blocks (with `at`).

`layoutPageJoins()` (reportsthatmatter-38s.10) is the first pass that reads it: a paragraph left split at a page break joins the one above when the layout says it runs on, where text alone cannot (a capital, digit, bracket or quotation-mark opening, or a run-on past a full stop). R1: the paragraph at the page foot stops mid-sentence, reaches within 5 em of the right margin, and the new page's first line is flush with the line under it (|indent| < 0.6 em), unlabelled ("57." "(b)" "7.44" "•"), in the same face. R2: it ends a sentence, but the page is justified, its last line runs to the margin (< 0.5 em) and the next line is flush, unlabelled, same face, more than four words. Paragraph and paragraph only, never into a numbered finding. `layoutPageJoins({ scanned: true })` lets an OCR layer's line sizes differ by a point. `layoutPageJoins({ referee })` takes a deterministic second opinion on the low-margin calls (`PageBreakCase`, keyed by `pageBreakKey`; meant for a committed cache, 38s.11); `decidePageBreak` and `findPageBreakLines` are the pure parts, for tools and tests.

**The page-break referee** (reportsthatmatter-38s.11, `src/referee.ts`). Opt-in per report: `layoutPageJoins({ referee: pageBreakCache(new URL("./referee/pagebreaks.json", import.meta.url)) })` in the report's `ingest.ts`. The cache is a committed JSON file of answers keyed by `pageBreakKey` (a hash of the two printed lines); ingest reads only each entry's `join`, never calls out, and a break with no entry keeps the rules' call, so a build is deterministic, offline and needs no key. Each decision carries a `confidence`: `low` (the `ambiguous` calls: an indent within a quarter em of the flush threshold, every R2 join, a line under the first line that is not the block's own, an unfinished short last line), `medium` (a flush first line in the same face after a finished sentence on a page R2 does not cover; a label only the layout sees, such as a bare number and a space, after an unfinished sentence) or `high`. Only `low` calls are put to the referee, or `low` and `medium` with `layoutPageJoins({ referee, refer: "medium" })`, so a cache cannot move a high-confidence call. On the adjudicated page breaks every rules error at a `low` call is out of reach (there are none); the `medium` calls hold 3 of the 4 development errors and 1 of the 22 held-out ones (site `docs/design/2026-10-03-pagebreak-referee.md`). Filling it is an offline step in the host (the site's `pnpm ingest referee <id>`): run the pipeline with the cache, take `referee.asked` (the cases put to it), send the unanswered ones through `refereePageBreaks(cases, transport, { model })`, and `writePageBreakCache` the answers. The library has no network code and no SDK: the host supplies a `RefereeTransport` (the Anthropic SDK, or `replayTransport(file)` for a recording made with `recordingTransport`). The prompt is `REFEREE_SYSTEM` plus `REFEREE_EXAMPLES` (real page breaks from the fixtures, development and PDF-only reports only); `describeCase` shows the model our two blocks and the layout's lines either side, and `REFEREE_PROMPT_ID` is stored with each answer. `refereeCost` prices a run's usage at list price.

`layoutMarkers()` (reportsthatmatter-b94) links the footnote markers the PDF sets as small raised digits: "companies.7", "Corp,12", "community.”1", "IS.”1410", "198562" (1985, note 62), which the text-only linkers leave bare because nothing but a word, a comma or a quotation mark sits before them. Each raised run in a body-size line (not one that opens its line: that is a note's own number) is found in its page's blocks by the words printed before it and linked when (1) a note with its number was collected on its page, or on the page either side when that page's own raised markers do not cite the same number, and (2) it is in the longest increasing run of the page's candidates (notes are cited in order, so a raised "2" in "km2" between 151 and 152 is not). A candidate whose words are not found is left alone. The layout is then the authority: the text linkers (`linkInlineMarkers`, `flushFootnoteMarkers`, the endnotes chapter linker) do not run, because what they add is the numbers the PDF does not raise ("105 dailies, 15 Sundays", "In short, 25 people"); `layoutMarkers({ textFallback: true })` runs them after it. With page scope, a page-foot "note" block on a page whose layout defines no note (no line opening on a raised number or a number in a smaller face) is put back in the body: Leveson's contents pages had been read as 84 notes. `layoutMarkers({ scope: "document" })` takes any note the report collected, for endnotes; it is only as good as the endnotes the report parses. `IngestResult.layoutMarkers` counts what it saw, linked and could not place, with every link's context for reading a sample against the page.

`typographicHeadings({ firstLevel })` (reportsthatmatter-a8l, `src/typographic-headings.ts`) cuts subsection headings out of the paragraph the text reading ran them into, from their typography. `pdftotext` sets a heading on its own line, but the block parser knows a heading only by its text (listed in the contents, numbered, all capitals); one set only by face and size, as Hillsborough's maroon 26pt and 21pt lines are, comes out as the first words of the next paragraph ("Recognition of the disaster 2.4.20 The first essential requirement…"). The pass reads the layout for lines larger than the body (1.15 times), not in the body's face, not italic, short, not a bare number, not ending a sentence; a face (family, size, weight, colour) is a heading style only when it recurs (5 lines on 3 pages: `minLines`, `minPages`); the styles are ranked by size and the largest takes `firstLevel`, each smaller one level deeper (`sizes: [26, 21]` declares which sizes are headings, largest first, where the largest face is a part or chapter title that the report's other passes read); a heading wrapped over lines is one heading. Each heading is then found in its page's blocks, and the block is cut at it when it opens the block or follows the end of a sentence (never from the middle of one), into the text before, the heading, and the text after; a block that is only the heading's words is promoted; a block already a heading is left alone; one not found is counted (`IngestResult.typographicHeadings`: `faces`, `split`, `already`, `unplaced`, each heading added with its context). It reads what every PDF has, not the PDF's tags, so it serves a tagged and an untagged PDF alike, and a hybrid's PDF-filled stretches (`fillGaps`) get their headings with the rest of the shadow. A heading it cuts is marked `layoutHeading`, which `fillGaps` reads: a subsection title that recurs through a report ("Settlement", "Conclusion") is not a running head, so it is kept though the edition has a heading with the same words (and a short heading's words turning up in nearby prose no longer count as a repeated phrase). A heading the edition holds right at the gap's edge, which the PDF repeats, is dropped. Opt-in: a report whose headings carry a textual convention needs nothing.

Three opt-in folio passes (reportsthatmatter-uw50, ssfk; `src/clean.ts`, `src/folios.ts`), for a page number the default reading misses or misreads. `parenFolios()` reads a lone "(3)" at the head or foot of a page as the page number and takes it out of the body (Challenger's chapter openers and Conclusions, whose folio stayed as a paragraph and left the next page's opening words above its marker). `pageHeadFolios({ above })` reads a running head "Page 7" alone on a line at the head of the page, and the line above it that matches `above` ("January 6, 2025"), as the folio (Jack Smith's appended letter). `foliosInStep()` drops a printed number that is out of step with the pages round it, so the gap-filler (d662) numbers the page from its neighbours: the offset (printed minus PDF page) is constant over a stretch of a continuously numbered report, and a run of fewer than three reads beside a longer run, or of up to eight between two stretches at one offset, is garble taken for a folio (an OCR'd figure page's "2", "0", "77"). Reports whose numbering legitimately changes offset for a short stretch should not declare it.

`typographicHeadings({ faces, relevel: true })` (reportsthatmatter-gqsy.4): with declared `faces`, a block the text reading already made a heading at another level takes the level its face declares (matched on letters and digits only, since the division reading adds a colon). The Grenfell Tower Inquiry's executive summary heads its account of each Part ("Part 3 / The testing and marketing of products (Chapters 15 – 29)") in a sub-heading face; read by its text as a division, each was a top-level section beside the volume's own Parts 1 and 2. Counted in `IngestResult.typographicHeadings.relevelled`.

`furnitureFaces(faces, { edge })` (reportsthatmatter-gqsy.4, `src/furniture-faces.ts`): a body pass that drops the lines the layout sets in one of `faces` (layout face keys, as `pnpm ingest page` prints them) within the top or bottom `edge` of the page (default 8% of its height), and nothing else. For a report whose running head names the chapter: the Grenfell Tower Inquiry's recto head ("Part 2 | Chapter 13: The Fire Safety Order", white Calibri 10pt on a banner) recurs only on one chapter's few rectos, so `runningFurniture` left the short chapters' heads in the text while stripping real headings that open many pages ("Introduction" under a chapter banner, "Part 3") and the banners' "Chapter 2" lines. A line elsewhere on the page with the same words (whitespace ignored) as a dropped head goes too. Needs the layout; opt-in.

`measureLayout(layout, result.blocks, result.footnotes)` is the layout oracle (`src/oracle.ts`): per page, the headings, footnote markers, paragraph starts and quotations the layout implies, set against what the pipeline produced, as nine counts (`headings-missed`, `headings-spurious`, `markers-unlinked`, `markers-spurious`, `paragraphs-oversplit`, `paragraphs-merged`, `quotes-spurious`, `quotes-missed`, `note-off-page`). It only measures. Pass `{ relink: false }` when the blocks come from `finalBlocks` (their links are the pipeline's own; otherwise it re-links them with `linkInlineMarkers`, which counts guesses the reader never sees where the pipeline did not run it). A marker counts in any line at the body's size and colour, italic or bold included (a case name). `note-off-page` (`{ noteOffPage: true }`, for a report whose notes are page footnotes, `hasPageNotes(def.passes)`; needs `finalBlocks` and the whole `result.footnotes`) pairs every `[^N]` with its definition exactly as the renderer does (`resolveNoteReferences`) and counts the references whose note was printed more than one page from the marker: the renderer's alignment takes early definitions when few of a chapter's markers are linked (reportsthatmatter-y0w9). Its thresholds are `ORACLE`; its precision per signal is in the site's `docs/quality-harness.md`.

## Golden pages and the page kit

A signal says "this looks wrong"; a **golden page** says "this page is right". Each report repo carries a `golden.yaml`: PDF pages whose true structure was read off the page image and recorded with who and when: the blocks that start on the page in order (type, heading text, how a paragraph opens and ends, the notes linked in it), the notes defined and the markers referenced there, and `must_contain` / `must_read` / `must_be_quote` / `must_not_be_quote` / `must_not_contain` / `separate` runs for the facts a block list cannot say (a table's rows, a quotation, furniture). `parseGolden(text)` reads one; `checkGoldenPage(page, finalBlocks(result), result.footnotes, { relink: !result.linkedText })` checks a page against a regeneration and returns the problems, the kinds of assertion that failed (`ASSERTION_KINDS`) and what each oracle signal should read there; `scoreOracle(rows)` is the oracle's precision and recall against those. The format is documented at the top of `src/golden.ts`.

A page the pipeline is known to get wrong carries `xfail: <bead>` and `xfail_only: [kinds]`: those assertions may fail, the rest must still pass, so a page that is red for a known reason still catches a new regression, and a fix that makes the known failure pass fails the check until the xfail comes off.

`finalBlocks(result)` is `result.blocks` with each block's text replaced by what the reader gets (`IngestResult.linkedText`): markers linked as `[^N]` (for an endnotes report that happens only on the serialised text), hyphens rejoined, OCR fixed. Compare block text with the page through it.

The page kit prints one page's layout lines beside the blocks made from it, so writing an entry takes minutes: `renderPage(id, layout, blocks, footnotes, volume, pdfIndex)`; `draftGolden(...)` is a first draft of the entry from what the pipeline made (the pipeline's reading, to be corrected against the image); `pageFixture(source, xml, blocks, footnotes, volume, pdfIndex)` cuts a `tests/fixtures/oracle/*.json` fixture. The site's `pnpm ingest page <id> <volume> <pdfPage> [--draft] [--fixture <name>]` runs them.

## A clean edition as the source (`cleanEdition`)

Where the publisher's own HTML (or tagged text) of a report exists, its text and structure are authored there, and the PDF cleaning passes have nothing to repair. `cleanEdition` (src/edition.ts, reportsthatmatter-ivg; design: the site's `docs/design/reference-editions.md` §2.1) serves such a report from the edition and keeps the PDF for what only it has:

```ts
import { cleanEdition } from "@rtm/ingest";
import { readCommissionHtml } from "./commission-html.ts"; // the report's own adapter

passes: [
  cleanEdition({
    dir: import.meta.dirname,            // the report repo
    encoding: "latin1",
    files: [{ path: "reference/raw/911Report_Ch1.htm", sha256: "…" }, …],  // checked before reading
    read: readCommissionHtml,           // files → { blocks, notes }
  }),
  …every PDF pass, unchanged…
]
```

- **Text and structure** come from the edition, as `EditionBlock`s (heading, paragraph, quote, list, contents, table; inline Markdown with `[^label]` markers) and `EditionNote`s that the report's adapter reads. What the markup means is a property of that source, so the adapter is report code; `htmlEvents` (a tolerant HTML 4 tokenizer), `inlineMarkdown` and `inlineText` (notes: the renderer sets them as plain text) are the pieces. A block the edition sets where the PDF's page put it (a figure, a caption, a box) carries `float: true`: a paragraph that stops mid-sentence, then only floats, then a paragraph, is served as one paragraph with the floats after it.
- **The PDF ingest still runs**, every declared pass, as the **shadow**: its `%%page%%` markers say which PDF page carries which printed number, and its furniture-free page text is what the edition is aligned to (`IngestResult.shadow`, `IngestResult.pageText`). Corrections apply to the shadow; they are judgements about the PDF's text.
- **Page anchors**: the edition's words are aligned to the PDF's with the scorer's monotone anchor alignment (`align`, promoted here from the site's `src/lib/score`), and each block is stamped with the printed page its first word is on. A page that starts inside a block is marked after it (and after any float still printed on the earlier page), as `mergeAcrossPages` does.
- **Typography the edition flattened**, only where there is one reading: an ASCII hyphen the PDF prints as an em or en dash between the same two aligned words; a space the PDF prints after punctuation the edition runs on ("Timeline,"Dec."); a line-end hyphen of the PDF the edition kept ("air-line's"), closed up only where the edition prints the word whole elsewhere and this is its only hyphenated spelling.
- **The PDF is the fidelity check.** `IngestResult.edition` (`EditionReport`) has the share of edition words aligned to the PDF, the edition's words the PDF never prints (OOV, as a word or two joined), the share of PDF words the edition holds, pages anchored, and the count of each typographic repair. Every stretch where the two disagree is a review-queue suspect (`edition text not in the PDF`, `PDF text not in the edition`) in `fidelity.md`: flagged, never resolved silently.
- **Notes printed under their paragraphs** (`notes: "page-foot"`, Saville): the shadow lifts such notes out of the page text and holds them as its footnotes, so the edition's notes would have nothing to align to at the back. With the option, the shadow's notes go back on their pages as a stream of their own (its linked markers taken out), and the edition's notes, which follow its body, are aligned to that stream; each edition note is then on the PDF page its first word is printed on (`Footnote.volume`/`pdfIndex`), which golden pages read. The default, `"back"`, is the 9/11 arrangement (endnotes in the body stream).
- **Notes printed after each chapter** (`EditionNote.after`, the January 6th Committee's Final Report): the edition's notes follow its body, but a report that prints each chapter's endnotes at the chapter's end has them interleaved with the body in the PDF, so a monotone alignment can match the body or the notes, not both (53% of that report's edition words aligned before, 98.7% after). The adapter sets each note's `after` to the index of the edition block the PDF prints it after (the chapter's last block); the alignment then reads the edition in the PDF's order, `fillGaps` counts those notes as part of the block they follow, and a page that prints only such notes gets no `%%page%%` marker (it names no served text, and its marker would pile up at the start of the next chapter with the rest of the chapter's notes pages). Notes without `after` follow the body as before; serving is unchanged.
- **Pages without a number, and pages the edition does not hold**: a PDF page the shadow read no printed number off, between two it did whose numbers run in step with the PDF's page order, is numbered by the pages around it (`fillPrintedGaps`; 9/11 gains pages 144, 324, 413 and 448 this way). Pages before the first one with a word of the edition (a title page, a contents the edition lacks) are not marked at all, and a repeated number's occurrence count is adjusted (`pages.frontMatterSkipped` in the report).
- **Gaps: what the edition lacks, filled from the PDF** (`fillGaps`, reportsthatmatter-ivg.3, Hillsborough). An edition that is incomplete (an archive that never captured some web pages; front matter the site never carried) says where with a `{ kind: "gap", reason }` block, placed by its adapter, which knows which of its files are missing. The alignment says what is missing, to the word: the PDF body text between the last aligned edition word before the gap and the first after it is filled with the **shadow's own blocks** (a block straddling the edge is cut at its first or last word inside), each carrying `source: { pdf: { volume, pdfIndex }, gap }` (and `Block.source: "pdf"` in `IngestResult.blocks`, against `"edition"`), so every served block says where its text came from. The notes the filled blocks cite come with them from the shadow's notes on their pages, relabelled `N-90xx` (rendered as N, never an edition's label); a marker whose note is not found is left as its bare number. Left out: a bare number (a page number or a marker on its own line), a heading or lone contents entry whose words are an edition heading's (a running head, a divider page repeating a chapter's title), and a block whose words the edition already prints within 100 blocks of the gap (a repeated phrase the aligner left unmatched). Each gap is a fidelity row (`edition gap filled from the PDF`: reason, blocks, words, notes, PDF pages) and an entry in `EditionReport.filled`. Text the PDF prints and the edition lacks *outside* a declared gap is never filled: it stays a `PDF text not in the edition` suspect, because an edition that leaves something out on purpose (a map's labels) looks the same to the alignment as one that lost it. The page markers need nothing special: filled blocks are the PDF's words, so they align exactly and the markers run on through them.
- **Strikethrough**: an `InlinePiece` with `strike: true` is set as `~~…~~` (Hillsborough's chapter 11 quotes police statements with their deletions struck through).
- **A quotation of several paragraphs** is a `quote` block whose text holds `\n\n` between its paragraphs: one blockquote, a paragraph to each.
- **Same output contract**: `full.md` with `%%page N%%` markers and notes under a closing `## Notes`; `IngestResult.blocks` (each on the PDF page its first word is printed on) and `linkedText`, so the layout oracle and golden pages measure the served text.

`losslessCheck` accepts a word that is in the source as a piece of a token or two tokens joined across a line-end dash or an apostrophe ("interceptors.The", "team—" / "Suqami", "Yousef ’s"): the edition spaces and closes up what the PDF's text layer does not. It moves no output; the gate's counts fall for PDF-built reports too, and no report's pass or fail changes.

## Block structure from a vision model (`visionStructure`)

A scanned report whose text layer is good on words and poor on structure (Challenger: paragraph starts lost at every indented line, notes run into the body, the report's own Issue/Findings labels read as prose) can take its block structure from a vision model's reading of the page images, page by page, while every word stays the text layer's. `visionStructure` (src/vision/, reportsthatmatter-jsqw; the measurements behind it: the site's `docs/design/2026-10-03-vision-structure-pass.md`, kyj3) reads the model output the report repo commits (granite-docling DocTags, `reference/vision/doctags.jsonl.gz`, written by the site's `scripts/vision/run.py --manifest`):

```ts
import { visionStructure } from "@rtm/ingest";

passes: [
  …every PDF pass, unchanged…,
  visionStructure({
    dir: import.meta.dirname,
    pack: { path: "reference/vision/doctags.jsonl.gz", sha256: "…" },   // checked before reading; each page's DocTags against its recorded hash
    // minAccepted: 0.8, strict: false, keepStarts: false, quotesFromPipeline: true (the defaults)
  }),
]
```

- **Verified, page by page.** Each page's model blocks are aligned to the pipeline's own text for that page (its lines once furniture and the body passes are off, page-foot notes included; `verify.ts`, ported from the site's verifier): a block is accepted at 75% of its words in the layer and no run of more than 8 missing (lenient; `strict: true` is 90% and 4). The layout is a second witness for which lines are notes (set at 0.88 of the body size or less).
- **Gated, page by page.** The page takes the model's structure only when at least `minAccepted` of its blocks are accepted, it is not a contents page, and the vision reading loses none of the pipeline's section headings (level 2 and 3: the report's sections and their slugs), none of its notes, and no text a correction finds there. `keepStarts: true` also refuses a page where the model has fewer paragraph starts than the pipeline (off by default: on Challenger the pipeline over-splits exactly the pages the model reads best, PDF p.68 has 48 starts for 16 paragraphs). Every other page keeps the pipeline's blocks.
- **The layer's words, always.** A gated page is rebuilt from the layer's characters: each layer token belongs to exactly one block, so every word is served once and none is the model's (`word count changed` keeps the pipeline's page if that ever fails). Accepted blocks take the model's type; a rejected stretch claims no structure and runs on into the paragraph before it, except where the pipeline also reads a paragraph start at an indented line after a full stop (two witnesses). A heading the pipeline also read keeps its text and level; a new one is a level-4 subhead (no section moves). A model "heading" that ends as a sentence or a lead-in ("Mr. Mulloy testified:") is a paragraph. A paragraph the pipeline set as a quotation (80% of its words) stays one.
- **Notes and markers.** A note is an accepted footnote block with the model's label (the model reads note numbers far better than this layer does); the layer's opening digits come off only where they are that label ("4 1 Ibid." for 41). A marker is set where the model puts one and the layer's characters look like one: the label's digits closed up to a lower-case word or closing punctuation, or set off after punctuation; never a number in running text ("13 of the 23 missions", "STS-3"). The page's notes replace the pipeline's notes for that page, in page order; a note's tail that ran over onto the next page stays with it. The text-only marker linker does not run on vision blocks and links only the note numbers the pipeline itself read.
- **Provenance and joins.** Each block from a gated page has `source: "vision"` (`Block.source`, the field cleanEdition's gap-fill uses for `"edition" | "pdf"`). The pipeline's page markers stand, and the page-break joins (`mergeAcrossPages`, `layoutPageJoins`) run over the mixed blocks as over any others: vision to pipeline, pipeline to vision, vision to vision. `IngestResult.vision` (`VisionReport`) lists every page's decision and why, and counts the source boundaries and how many the joins closed; `renderVisionReport` writes it out (the site's `pnpm ingest run` puts it in `reference/vision/hybrid.{md,json}`).
- **Relation to `cleanEdition`.** That mode replaces a report's text and structure with an edition's and keeps the PDF for pages and the fidelity check; this one keeps the PDF's words everywhere and swaps only the structure of the pages that pass the gate. They do not combine (`pipeline()` refuses both, and refuses `visionStructure` with `paragraphNotes` or `endnotes`). Whether to serve the model's words where it reads better than the layer is a decision (the site's docs/decisions/0011, fc3x), not an option here.

## Rendering and publishing

`full.md` is the ingestion pipeline's output and a report repo's own
authority — but it is not what a reader sees. Turning it into what
[reportsthatmatter.org](https://reportsthatmatter.org) actually serves, and
getting that in front of readers, are two more steps this library covers:

```ts
import { renderArtifacts } from "@rtm/ingest";

const { meta, fullBody, fragments } = renderArtifacts(readFileSync("full.md", "utf8"));
```

`meta` is the section list, word count, and the paragraph→section lookup a
`?p=` link is routed through; `fullBody` and `fragments` are the report's
content with **no site layout in either** — the app owns the page, the report
owns the text. Paragraph ids — the thing a citation actually resolves through
— are generated here, in the pinned library, specifically so that an
id-affecting change is a version a report adopts deliberately, the same way a
pipeline change already is.

**Publishing** takes that output live, without a site deploy:

```bash
RTM_PUBLISH_SECRET=<the site's PUBLISH_SECRET> \
  pnpm exec rtm-publish <report-id> --base https://reportsthatmatter.org
```

Run from the report repo's own root, where `full.md` lives. It renders that
file, uploads the result under a content hash the site's endpoint verifies
before it goes live (a publish that would 404 in production is refused, not
shipped half-finished), and points the site at it. `--status` shows what is
currently being served for a report; `--rollback <hash>` re-points at any
version still stored, without re-uploading. See
[reportsthatmatter/reportsthatmatter's AGENTS.md](https://github.com/reportsthatmatter/reportsthatmatter/blob/main/AGENTS.md#publishing-a-report-how-it-works-now)
for the full account, including where the secret lives and the one sharp
edge worth knowing before touching any of this: **a report published to R2 is
not touched by a site deploy**, so it can go stale relative to this repo's own
`full.md` until someone explicitly republishes it.

## Checking your work

```bash
pnpm ingest run <id>        # rebuild one report from its definition
pnpm ingest verify          # fidelity gates against the real source PDFs
pnpm ingest check           # has any report's output moved?
pnpm ingest baseline <id>   # accept a move, after reading the diff
```

`pnpm ingest check` is the corpus regression signal, and it runs in the site
repo's `verify.sh`. A change that moves any report's output fails until its baseline
moves with it — the whole corpus regenerates in about five seconds, so there
is no excuse for not knowing. It exists because a fix aimed at one report
once changed three others silently.

Two tiers of test sit under it here: synthetic unit fixtures in
`tests/pipeline.test.ts`, and **golden page fixtures** in
`tests/fixtures/pages/` — real pages from the corpus, chosen for being hard.
Every synthetic test passed while a real defect shipped; that is what the
golden pages are for, and why they live with the library rather than with the
site.

```bash
pnpm test         # unit + golden page fixtures
pnpm typecheck
pnpm build        # dist/, what consumers import
pnpm check-dist   # dist/ is committed — fails if it is behind src/
```

**`dist/` is committed deliberately.** Consumers install this by git URL, and a
`prepare` script would make every one of them approve a build step keyed by a
content hash that changes on each release. Shipping the compiled output makes
the dependency plain files. `pnpm check-dist` fails if `dist/` is behind `src/`.

### Releasing

Merge the PR first (including any `dist/` rebuild), then, from an up-to-date `main`:

```bash
pnpm release 0.15.0 --dry-run   # run every check and the build, change nothing
pnpm release 0.15.0             # for real
```

`pnpm release <version>` refuses unless you are on `main`, level with `origin/main`, with a clean tree and no existing `vX.Y.Z` tag (local or on origin). It then runs `pnpm build`, fails if that changed `dist/` (land a `chore: rebuild dist` PR first), runs the tests, bumps `package.json`, commits `chore: release vX.Y.Z`, tags it, and pushes the commit and the tag. Never tag a PR branch: a squash-merge leaves that tag unreachable from `main`.
